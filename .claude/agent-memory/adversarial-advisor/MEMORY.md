# 이 프로젝트가 실제로 저지른 실패 유형 — 색인

> 모두 **실제로 일어났고 뒤늦게 잡힌** 것들이다. 새 주장을 볼 때 이 목록부터 대조하라.
> 각 항목의 사건 상세·수치·재현 명령은 **`cases.md`** 에 있다. 해당 유형이 걸렸을 때만 열어라.

## 감사 절차 (권장 순서)

1. **아티팩트 존재 확인** (H) — 주장된 수치를 `grep` 으로 저장소 전체에서 찾아라.
   코드도 JSON 도 없으면 그 자체가 blocker다.
2. **재현** — JSON 원자료로 보고된 통계를 직접 재계산.
3. **독립성 확인** (M) — n 이 케이스×시드 곱이면 ICC 를 재라.
4. **대조군 만들기** (A·L·N) — 주장된 메커니즘을 **뺀** 변이를 실제로 돌려라.
   가장 결정적인 한 수다. 이 프로젝트에서 두 번 다 헤드라인이 무너졌다.
5. **조건 흔들기** (K) — 계측·비율 주장은 τ·창·seed 를 2~3개로 바꿔 범위를 보고.

# 이 프로젝트가 실제로 저지른 실패 유형

> 모두 **실제로 일어났고 뒤늦게 잡힌** 것들이다. 새 주장을 볼 때 이 목록부터 대조하라.
> 날짜는 발견 시점.

## A. 순환 논증 — 지표가 손실이 최적화한 양

**2026-08-13.** 위상 손실 디퓨전의 개선 지표 4개 중 **3개(밀도·cycle 프로파일·H₀ 구간 수)가
손실이 직접 회귀한 양**이었다. "9.1배 개선"을 헤드라인으로 썼는데 독립 증거가 아니었다.
손실과 독립인 지표는 시간축 autocorr 하나뿐이었다.

→ **결말**: ablation 을 돌리니 손실 없는 `conv` 가 이미 전부 달성했다
(JS_profile 0.00217 vs conv_topo 0.00213, 부트스트랩 95% 구간 겹침).
**애초 가설(위상 손실이 공)이 틀렸고 공은 아키텍처에 있었다.**

→ **물어라**: "이 지표를 손실이 직접 건드리는가? 안 건드리는 지표는 무엇인가?"

## B. 적합과 적용의 자가 다름

**2026-08-13.** τ-leaping propensity 를 **연속 OM 활성합**(평균 3.69)으로 적합해 놓고
**이진 활성수**(모티브 OM 은 평균 1.30)에 적용했다. λ 가 3.53 대신 0.87 이 되어
**음이 41% 사라졌다.** 그런데 밀도비는 오히려 올라가 "성공"처럼 보였다.

→ **물어라**: "적합할 때 쓴 입력과 적용할 때 쓰는 입력이 같은 자인가?"
→ **경고 신호**: 총량이 크게 변했는데 비율 지표만 좋아진 경우.

## C. 동어반복 비교

**2026-08-13.** "낯선 모티브 D 가 모든 쌍에서 가장 멀다"고 보고했다. 그런데 모티브가
**시간의 26.7%를 직접 차지**하므로 전 영역 프로파일 JS 에는 "내가 넣은 게 거기 있다"가
섞여 있었다. 마스크 **밖**만으로 다시 재니 **A–D 가 0.087 → 0.0037 로 최소**가 되어
순위가 뒤집혔다.

→ **물어라**: "측정 영역 안에 내가 심어 넣은 것이 포함돼 있는가?"

## D. 평균이 신호를 지움

**2026-08-13.** 모티브 통제 효과를 밀도비 **평균**으로만 봤다. 모티브별 OM 지시비가
0.58~1.61 로 양쪽으로 갈리는데 평균은 1 근처라 "통제 실패"로 읽혔다.
올바른 질문은 "커졌나"가 아니라 **"지시를 따라가나"(상관)** 였고,
상관으로 재니 r = −0.21 → **+0.73** 이었다.

→ **물어라**: "평균 대신 상관·분산·개별 분포를 봐야 하는 것 아닌가?"

## E. 조용한 쓰기 손실 (numpy)

**2026-08-07.** `np.zeros_like` 는 입력의 **메모리 순서를 물려받는다**(order='K').
torch `permute` 결과를 넘기면 비연속이라 `out[i].reshape(-1)` 이 **뷰가 아니라 복사본**이
되고, 쓰기가 예외도 경고도 없이 사라진다. **모든 변이의 density 가 0.0 으로 보고됐다.**

→ **확인법**: `np.shares_memory(out[i].reshape(-1), out)`
→ **일반화**: 결과가 정확히 0 / 정확히 1 / 완전 균일이면 계산이 아니라 **배선**을 의심하라.

## F. 샘플러 관행을 논문 본문으로 오인

**2026-08-07.** DDPM 역방향에서 x̂₀ 를 [-1,1] 로 자르는 것을 "Ho et al. 2020 eq.7" 이라고
적었다. 사후평균 **공식**은 맞지만 **클리핑은 저자 공개 구현·Improved DDPM·diffusers 의
`clip_sample` 관행**이지 논문 본문이 아니다.
(참고: 클리핑 누락 자체는 진짜 버그였다 — 샘플이 0/1 로 포화됐다.)

→ **물어라**: "이게 논문 본문에 있는가, 구현 관행인가?"

## G. 결론을 감당 못 하는 표본

**2026-08-13.** "통제 강도를 두 배로 올려도 자유도가 안 줄었다"고 결론냈는데
조건당 표본이 **변주 2개 = 쌍 1개**였다. 같은 조건 안의 산포조차 못 쟀다.
정확한 표현은 "차이 없음"이 아니라 **"판별 불가"**.

→ **물어라**: "이 표본으로 이 결론을 낼 수 있는가? 신뢰구간은?"

## H. 문서 수치에 아티팩트가 없음

**2026-08-13.** 보고서 §6 의 수치(132.5 / 0.8251 / 0.00301)가 **콘솔 재실행 산출물**이었고,
저장소에 커밋된 `topo_diffusion_results.json` 은 **버그 시절 20에폭 산출물**(density 0.0)이었다.
게다가 콘솔 값은 16표본, 정식 아티팩트는 64표본이라 수치도 달랐다(127.9 / 0.8232 / 0.00282).

→ **물어라**: "이 표의 수치가 커밋된 JSON 에서 나오는가? 그 JSON 은 최신 코드 산출물인가?"

## I. 검증 자체가 같이 틀림

**2026-08-13.** JS↔파이썬 샘플러 패리티 검증이 17항목 전부 통과했는데,
respace(200→50) 후 **모델에 재배치 인덱스(0..49)를 타임스텝으로 넘기는 버그**를 못 잡았다.
파이썬에 respace 가 없어 참조 구현이 **JS 동작을 그대로 복제**했기 때문이다 — 둘이 같이 틀렸다.

→ **물어라**: "참조 구현이 검증 대상과 독립인가, 아니면 베낀 것인가?"

## J. 프로젝트의 오래된 전제도 틀릴 수 있다

**2026-08-10.** "hibari 의 가치 = 두 성부의 음역 분리" 가 6곳(메모리 2·문서 3·코드 2)에
퍼져 있었는데, 실제로 재보니 **두 성부의 pitch 집합이 완전히 동일**했다
(둘 다 [52,81], 교집합 17 = 합집합 17). 분리는 음역이 아니라 **시간(위상)** 이었다.

→ **물어라**: "이 전제를 실제 데이터로 확인한 적이 있는가, 반복 인용된 것인가?"

## K. 계측하면 다른 게 나온다

**2026-08-13.** QMC 저불일치 추출이 왜 안 통하는지 계측하다가, 노트 결정의 **81%가
`random.choice(intersect_pool)`** 로 가고 튜닝된 온도 T=3.0 은 **19% 에만** 걸린다는 걸
발견했다. 원래 가설(QMC)은 유의하지 않았지만(p=0.31), 계측에서 나온 발견을 고치니
음고 JS **−7.9% (p=0.007)** 였다.

→ **교훈**: 가설이 실패했을 때 "왜 실패했나"를 계측하면 종종 더 큰 게 나온다.
   실패한 실험을 그냥 버리지 말라고 조언하라.

# Ponytail 규칙 — 최소 코드 원칙

출처: https://github.com/DietrichGebert/ponytail (MIT). 2026-08-15 사용자 지시로 채택.
저장소의 훅·스킬을 설치하지 않고 **규칙만** 이 프로젝트에 맞춰 옮겨 적었다.

## 사다리 — 문제를 완전히 이해한 **뒤에** 오른다

첫 번째로 걸리는 칸에서 멈춘다.

1. **애초에 만들어야 하나** (YAGNI)
2. **이 저장소에 이미 있나** — 기존 헬퍼·패턴 재사용
3. **표준 라이브러리가 하나**
4. **플랫폼 기본 기능이 하나**
5. **이미 설치된 의존성이 하나** — `numpy` / `scipy` / `torch` / `pretty_midi` / `music21`
6. **한 줄로 되나**
7. 그제서야 **최소한만** 쓴다

## 규칙

- 요청하지 않은 추상화 금지
- 새 의존성은 피할 수 있으면 추가하지 않는다
- 요청하지 않은 보일러플레이트 금지
- **추가보다 삭제**, 영리함보다 지루함, 파일은 적을수록
- 작동하는 **가장 짧은 diff**가 이긴다 (단, 문제를 완전히 이해한 뒤에만)
- 복잡한 요청은 되물어 실제 필요를 확인한다
- 의도적으로 낮춘 것은 `ponytail:` 주석으로 **한계와 올릴 방법**을 함께 적는다
- 버그는 증상이 아니라 **근본 원인**을 고친다. 호출부를 전부 grep 해서 공유 함수 한 번에 고친다
  (개별 호출부 패치보다 diff 가 작다)

## 절대 줄이지 않는 것

- **문제를 완전히 이해하는 일** ← 이 프로젝트에서 실제로 사고가 난 지점은 항상 여기였다
- 신뢰 경계에서의 입력 검증 · 데이터 손실을 막는 에러 처리 · 보안 · 접근성
- 명시적으로 요청된 기능

## 검증

비자명한 로직에는 **돌아가는 확인 하나**. 로직이 깨지면 실패하는 가장 작은 것.
프레임워크·픽스처 없이 assert 스크립트 하나면 된다.
자명한 한 줄짜리에는 테스트를 붙이지 않는다.

예: `tools/verify_js_algo1.mjs` + `tools/verify/score_js_algo1.py` — 실제 배포 JS 를 돌리고
원본 파이썬 지표로 채점하며, 수정 전 규약을 대조군으로 재현해 FAIL 을 보여준다.

## ⚠ 이 프로젝트에서의 예외 — 연구 기록은 보일러플레이트가 아니다

`experiments/run_*.py` 의 다음은 **줄이지 않는다.** 이것들이 오늘까지 네 번 잘못된 헤드라인을 잡았다.

- **사전 예측**(`PREDICTION`) — 실행 전에 적어야 사후에 말을 바꾸지 않는다
- **메커니즘 뺀 대조군** — 주장한 메커니즘만 제거한 팔
- **한계 서술** — 무엇을 재지 못했는지
- **원본 JSON 저장** — 재분석 가능해야 한다

즉 **코드는 최소로, 기록은 충분히.** 사다리는 구현에 적용하고 과학적 기록에는 적용하지 않는다.

## 출처의 벤치마크에 대해

README 는 54% LOC 감소 등을 보고하지만 **n=4 회, 저장소 1개(full-stack-fastapi-template),
티켓 12개, Haiku 4.5** 조건이고, 저장소 스스로 "과설계 여지가 있는 과제(date picker)에서 94%,
이미 최소인 코드에서는 0 에 가깝다"고 밝힌다. **일반 법칙이 아니라 과제 의존적 평균**으로 읽는다.
이 규칙을 채택하는 근거는 그 수치가 아니라 원칙 자체의 타당성이다.

# 참여 백엔드 — 선택 근거와 설정 절차

목표: **100명에게서 응답을 받는다.** 막고 있던 것 두 가지.

- `arena/` 의 20표가 그 브라우저의 localStorage 에만 있어 아무도 못 본다
- `echo.html` 에서 사람들이 놓은 배치를 남길 곳이 없다

GitHub Pages 는 정적 호스팅이라 서버 쪽 저장을 직접 할 수 없다. → 외부 저장소가 필요하다.

---

## A. 선택지 비교

기준: ① 무료 한도로 100명 충분한가 ② 정적 페이지에서 바로 부를 수 있나
③ 사람이 설정하는 단계 수 ④ 개인정보 없이 되나

| | Firebase Firestore | Supabase | Cloudflare Worker + D1 | **Google Apps Script + 시트** |
|---|---|---|---|---|
| 무료 한도 | 하루 읽기 5만 · 쓰기 2만 **문서** | DB 500MB, 요청 수 무제한 | 하루 요청 10만, D1 읽기 500만·쓰기 10만 **행** | 동시 실행 30, 호출당 6분 |
| 100명에 충분? | ⚠ **읽기가 모자란다** (아래) | ✅ | ✅ | ✅ |
| 정적 페이지에서 | REST(fetch) 또는 SDK | REST(fetch) | 우리가 짠 Worker 를 fetch | fetch (text/plain → preflight 없음) |
| 설정 단계 (추정) | 5 (프로젝트·DB·보안규칙·키) | 5 (프로젝트·테이블·RLS 정책·키) | 7+ (계정·wrangler CLI·D1 생성·스키마·배포) | **5** (시트·스크립트 붙여넣기·배포·승인·URL) |
| 개인정보 없이 | ✅ | ✅ | ✅ | ✅ |
| 치명적 약점 | 문서 단위 과금 | **7일간 DB 질의가 없으면 프로젝트가 일시정지**된다 | 서버 코드를 우리가 짜고 배포해야 한다 | 호출이 느리다(리다이렉트 1회) · 시트 주인의 구글 계정에 묶인다 |
| 결과 분석 | 콘솔/내보내기 | SQL | SQL | **스프레드시트 그대로** |

**Firestore 의 읽기 문제.** 사다리는 모든 표를 시간순으로 다시 돌려서 만든다(Elo 재생).
Firestore 는 문서 하나를 읽을 때마다 과금한다. 100명 × 20표 = 표 2,000개면
사다리 한 번 여는 데 읽기 약 2,000회 → **하루 25번 열면 무료 한도가 끝난다.**
(표를 합계 문서로 모으면 피할 수 있지만, 그러면 보안 규칙으로 "+1 만 허용"을 검증해야 하고
누가 누구를 이겼는지라는 **연구 데이터 자체가 사라진다.**)

**Supabase 의 일시정지.** 참여는 몰려서 오다 몇 주 끊기기 쉽다. 끊긴 사이 7일이 지나면
멈추고, 그 뒤 온 사람의 표는 사람이 대시보드에서 깨울 때까지 **로컬에만 쌓인다.**
(깨우는 크론을 따로 돌리면 피할 수 있지만 그것도 설정할 것이 하나 더 늘어난다.)

### 추천: Google Apps Script + 스프레드시트

- 읽기 한 번 = 호출 한 번 (행 수와 무관) → 사다리 재생에 과금 걱정이 없다
- 멈추지 않는다
- 데이터가 **스프레드시트로 바로 쌓인다** — 연구자가 그대로 열어 분석한다
- 서버 코드 76줄, 붙여넣기만 하면 된다

치르는 값: 호출이 1~2초 걸릴 수 있다(여기서는 측정 못 함). 그래서 페이지는
**서버를 기다리지 않는다** — 내 기록으로 먼저 그리고, 서버 응답이 오면 다시 그린다.

## B. 설정 절차 (사람이 해야 한다 — 약 10분)

1. 구글 계정으로 **새 스프레드시트**를 만든다 (`sheets.new`). 이름은 아무거나.
2. 메뉴 **확장 프로그램 → Apps Script**. 열린 편집기의 `Code.gs` 내용을 전부 지우고
   `tda_pipeline/tools/backend/apps_script.gs` 내용을 붙여넣고 저장.
3. 오른쪽 위 **배포 → 새 배포** → 유형 톱니바퀴에서 **웹 앱**.
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포**
4. 권한 승인 창이 뜬다. "확인되지 않은 앱" 경고가 나오면 **고급 → (프로젝트 이름)(으)로 이동**.
   스크립트가 요구하는 권한은 **이 스프레드시트** 접근뿐이다.
5. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해
   `tda_pipeline/shared/remote.js` 의 `ENDPOINT` 자리에 넣는다:
   ```js
   var ENDPOINT = window.REMOTE_ENDPOINT || 'https://script.google.com/macros/s/…/exec';
   ```
   커밋 → main 에 push. (이 URL 은 비밀이 아니다 — 페이지에 박혀 공개된다.
   쓸 수 있는 것은 형식 검사를 통과한 이벤트뿐이다.)

**확인:** 브라우저 주소창에 `<URL>?kinds=vote` → `{"ok":true,"events":[]}` 가 보이면 된다.
그 다음 `arena/` 를 열면 하단 문구가 "모두와 함께 쌓입니다"로 바뀌고,
그 브라우저에 쌓여 있던 기록(예전 20표 포함)이 시트의 `events` 탭에 올라온다.

⚠ **서버 코드를 고칠 때는 "새 배포"가 아니라 배포 관리 → 연필 → 버전: 새 버전.**
새 배포를 만들면 URL 이 바뀌어 5번을 다시 해야 한다.

## 데이터 형식 (시트 `events` 탭)

| server_time | kind | id | uid | t | data |
|---|---|---|---|---|---|
| 서버 도착 시각 | 종류 | 이벤트 id | 브라우저 난수 | 브라우저 시각(ms) | JSON |

| kind | data | 공개(GET)? |
|---|---|---|
| `sow` | `{id, parent}` — id 가 곧 유전자 문자열 | ✅ |
| `vote` | `{a, b, w}` — 조각 id 둘과 이긴 쪽 `'A'`/`'B'` | ✅ |
| `legacy` | 예전 판(arena.v1)의 합계 — `{votes, votedIds, pieces[]}` | ❌ 연구자만 |
| `echo` | `{drops:[{x,y,li,per,at}], lang, end}` — 한 판에 놓은 점 | ❌ 연구자만 |

- **참여자 수** = `uid` 고유값 수. 이름·이메일·IP 는 받지도 적지도 않는다.
- 같은 이벤트가 두 번 올라갈 수 있다(전송 성공 직후 창을 닫은 경우). **`id` 로 중복 제거**하고 분석할 것.
  페이지는 이미 그렇게 읽는다.

## 한계 (정직하게)

- **예전 20표는 Elo 로 재생되지 않는다.** arena.v1 이 "누가 누구를 이겼나" 없이 합계만
  저장했기 때문이다. `legacy` 행으로 연구자에게는 보이지만 공용 사다리 점수에는 안 들어간다.
  그 판에서 **심은 조각**은 `sow` 로 되살아나 사다리에 들어간다.
- **스팸 방어는 형식·크기 검사뿐이다.** 누가 마음먹고 표를 쏟으면 막지 못한다.
  필요해지면 `doPost` 에 uid 당 하루 상한을 넣는다.
- **실제 구글 서버로는 시험하지 못했다** (이 환경에서 google.com 접속이 막혀 있다).
  대신 `apps_script.gs` 를 **그대로** node 에서 돌리는 모의 서버로 전 구간을 확인했다:
  `node tda_pipeline/tools/verify_remote.mjs` (저장소 루트에서, 25항목).
  모의 서버는 Apps Script 처럼 preflight(OPTIONS)를 거절한다. 구글의 302 리다이렉트는
  재현하지 않았으므로 **배포 후 위 "확인" 단계를 한 번은 사람이 해야 한다.**

## 0. 사용자가 원하는 것 (내 이해)

1. **공감각** — 보는 것과 듣는 것이 하나다. 화면의 모든 사건이 소리의 사건이고, 그 반대도 그렇다.
2. **생명체는 자기가 사는 환경을 몸에 흡수한다** (문어 다리 = 파도). hibari 에 사는 생명체라면
   hibari 의 구조가 곧 몸이어야 한다. 종이 여럿 있다.
3. **Tonnetz 위의 국소 규칙**으로 산다. 이산적이어도 된다. 플레이어가 직접 손을 대고,
   생명체는 위상(TDA)에 따라 **모양을 바꾸며 이동**한다. TDA 밖의 국소 규칙도 있다.
4. **음악은 우리 메커니즘**(고리 → 중첩행렬 → Algorithm 1)으로 난다. 여기에 **Markov 연쇄**를 접목한다.
5. z축에 뜻이 있으면 3차원.
6. 별자리(판 8)처럼 "이미 그려진 그래프에서 점 고르기" 가 아니다. echo.html 에 기대지 않는다.

## 2. 근거 실측 (착수 전)

### 2.1 두 손을 32스텝 원으로 접으면 — 날개와 말린 팔

각도 = (t mod 32)/32 · 360°, 반지름 = 모듈 번호. 두 손은 **같은 무늬**(4·1·4·1… 12칸 울림 + 4칸 쉼, 두 번)를
치고 주기만 **32 · 33** 이다 (논문 §4.7.4 사용자 분석, 실측 `inst1` 첫 모듈 onset 수
`4 1 4 1 4 1 4 1 4 1 3 1 0 0 0 0 | 4 1 4 1 4 1 4 1 4 1 4 1 0 0 0 0`).

| | 32 틀 | 33 틀 |
|---|---|---|
| 오른손 (32) | **곧은 두 날개** — 부채 둘, 사이에 쉼 두 줄기 | 나선 |
| 왼손 (33) | **말린 팔** — 모듈마다 1/32 바퀴씩 돈다 | 곧은 두 날개 |

→ 날개가 말리는 것은 **자기 주기와 환경(박자틀) 주기의 어긋남**이 몸에 흡수된 것이다.
박자틀과 맞는 오른손은 곧게 편 날개(종달새), 한 칸 어긋난 왼손은 파도처럼 말린 팔(문어).
Lenia 분류로 보면 **Pterifera(날개 벌레)** 와 **Helicidae("회전하는 Pterifera", Chan 2019)** 의 관계와 같다 —
오비움 대신 이 두 과를 쓰는 이유다. 세 번째 과 **Circidae(고리 벌레)** 는 H₁ 고리 그 자체라 몸 위의 빛 고리로 쓴다.

### 2.2 Tonnetz 거리 고리는 격자 위를 기어간다

정본 경로(`build_overlap_bundle`, `use_decayed=False`)로 두 거리의 고리를 다시 계산하고,
PH 원 변 목록에서 순회 순서를 복원해 이웃한 두 음의 **음높이 류 Tonnetz 걸음 수**를 셌다
(`scratchpad/tonnetz_probe.py`, 탐색용).

| 거리 | K | 순회 복원 | 걸음 0 (같은 음이름) | 걸음 1 (이웃) | 걸음 2 (건너뜀) | 국소 |
|---|---|---|---|---|---|---|
| **tonnetz α=0.5** | **41** | 34/41 | 78 | 115 | **0** | **100%** |
| dft α=0.25 (정본) | 14 | 14/14 | 2 | 34 | 30 | 54.5% |

→ **Tonnetz 고리를 쓴다.** 정본 DFT 고리는 음높이 류 정보가 없어(DFT 감사, 커밋 6ad799e) 격자 위에서 절반이 건너뛴다.
Tonnetz 고리의 걸음 78개(40%)는 음이름이 같고 옥타브나 길이만 바뀐다 — **z 축이 뜻을 갖는다.**
⚠ 캐시 `cache/metric_tonnetz.pkl` 은 K=47 이다. 설정이 다르다(정본 경로 재계산은 41). 캐시를 쓰지 않는다.

### 2.3 세계 — 6 × 10.39 토러스

Tonnetz 삼각격자(skew 좌표 c=5도, r=장3도, 음이름 = 7c+4r mod 12)를 주기 **(0,6)·(12,−6)** 으로 감는다.
두 주기 벡터는 직교하고(길이 6, 10.392) 칸은 **72개, 음이름마다 6번**. hibari 7음 칸(42개)에만 산다.
30° 돌리면 장3도가 세로, 5도가 30° 사선, 단3도가 −30° 사선이다.

## 3. 설계

### 3.1 공간 (3차원)
- 바닥 = Tonnetz 토러스(음이름 = 화성). 높이 z = 음높이(52→0, 반음당 0.13).
  근거: 높은 음이 "위" 라는 감각은 **자연 청각 장면의 통계**에서 왔다 (Parise, Knorre & Ernst 2014, PNAS).
  사용자의 문장 — 생명체는 환경을 몸에 흡수한다 — 과 같은 구조다. 우리 지각도 환경을 흡수했다.
- 한 hibari 음 (pitch, dur) = 바닥의 음이름 칸 하나 + 높이 하나. 같은 음이름의 여섯 칸 중 어디인지는 걸어온 길이 정한다.

### 3.2 생명체
- **종달새 = 오른손**: 리듬 고리 32칸 (위 무늬). **문어 = 왼손**: 33칸 (같은 무늬 + 쉼 한 칸).
- 몸 = 부른 음의 역사. 점 하나 = 한 번의 울림: 각도 = (t mod 32)·360°/32 (**박자틀은 둘 다 32**),
  반지름 = 나이, 크기 = 화음 크기, 색 = 음이름. → 종달새는 곧은 날개, 문어는 말린 팔이 **저절로** 된다.
- 알에서 깰 때 hibari 그 손의 최근 6모듈 리듬을 기억하고 태어난다(몸이 처음부터 보이게). 이후 점은 제 노래로만 쌓인다.
- 몸 위의 빛 고리(Circidae): 최근 부른 음이 어떤 고리를 켰는지 — 켜진 고리 수만큼 동심원.

### 3.3 움직임 — 고리-Markov 연쇄 (G2)
- 고리 k 의 순회 (v₀…v_{m−1}) 에 **곡의 시간 방향**으로 향을 준다: 원곡 각 손의 이웃 onset 쌍이
  순방향 변인 수 − 역방향 변인 수 ≥ 0 이면 순방향.
- 가중 w_k = 원곡에서 그 고리의 평균 연속 활성도. 전이 P(i→j) ∝ Σ_k w_k·[i→j ∈ C_k]
  (Kalpazidou 순환 표현 — 정상 흐름이 곧 고리 순환들의 합이다).
- **고리를 이어 탄다**: 지금 탄 고리를 확률 ρ=0.8 로 계속 탄다 (한 바퀴를 돌아야 먹는다, §3.5).
  갈림길(고리 교차 77%, 논문 §4.7.5)에서만 바꿔 탄다. 바꿔 탈 때 이웃 칸의 **먹이·발자국**이 쏠림을 준다.
- 순회 복원 실패 7고리는 격자 국소 걸음만으로 해밀턴 순환을 찾아 채운다(`reconstructed` 표시). 없으면 Markov 에서 뺀다.

### 3.4 소리 — 우리 메커니즘 (G3)
- 스텝 = 8분음표, hibari 템포(66 BPM, 454.5 ms). 생명체는 제 리듬 고리가 켜진 박에 운다.
- 한 박에 c 음 (리듬 고리 값 1~4): **머리 한 음**은 고리-Markov 한 걸음. 나머지 c−1 음은
  **Algorithm 1**: 최근 8스텝에 부른 음 → 고리 활성도(`overlap.py` 연속 정의, 희귀도 가중) → τ=0.35 →
  한 행 → `GenerationAlgo1.algorithm1` (교집합 = 공유 가중 합집합).
- 옥타브·길이는 hibari 음(pitch, dur) 그대로. 높이 z 는 부른 음높이.

### 3.5 되먹임 한 쌍 (G6)
- **강화**: 고리를 한 바퀴 돌면(머리가 탄 고리의 시작 음으로 돌아오면) 기운 +. 기운이 차면 **알을 낳는다 — 다른 손**
  (종달새가 문어를, 문어가 종달새를). hibari 의 두 손이 짝이다.
- **균형**: 우는 박마다 기운 −(부른 음 수에 비례). 한 칸에 둘이 서면 둘 다 더 잃는다. 먹이는 퍼지며 사라진다.
  기운이 다하면 몸이 흩어진다.
- 도넛(Raworth): 기운이 바닥(0) 아래로 가면 죽고, 천장(1)을 넘으면 알로 나뉘어 안쪽으로 돌아온다.

### 3.6 국소 규칙 (G7, TDA 밖)
- **먹이 장**: 문지른 칸에 먹이. 매 스텝 이웃 6칸으로 퍼지고(확산) 줄어든다(감쇠). 격자 CA.
- **발자국**: 부른 음의 칸에 발자국이 남고 천천히 사라진다. 다른 생명체는 갈림길에서 발자국을 따른다.
  → 앞선 생명체의 길을 늦게 따라가면 **같은 가락을 늦게 부른다** — hibari 두 손의 관계. 기대일 뿐, §5 V3 로 잰다.
- **다툼**: 한 칸 한 생명체. 밀리면 옆 칸으로.

### 3.7 개입 (G5)
- **누르기**: 그 칸의 음이 즉시 울린다(탭 전용 목소리). hibari 7음 칸이면 알이 깬다 — 종달새·문어 번갈아.
  다섯 검은 음 칸이면 소리만 나고 알은 깨지 않는다.
- **끌기**: 생명체를 잡아 다른 칸에 놓는다. 그 칸에서 가장 가까운 hibari 음으로 이어 걷는다.
- **문지르기**: 빈 격자를 끌면 먹이 길. 생명체가 고리를 따라 그쪽으로 간다(고리 밖으로는 못 간다).

## 4. 센서 (CLAUDE.md, 착수 전)
1. **왜 내일 또 오나** — 내가 깨운 종달새와 문어가 내가 문지른 길로 가며 hibari 같은 노래를 부르니까. 둘이 서로를 따라 부르니까.
2. **첫 조작까지 글자** — "눌러서 깨우세요" 8자.
3. **누름 → 소리** — 즉시(탭 전용 목소리, 스케줄 없이).
4. **손잡이** — 없다. 누르기·끌기·문지르기는 손가락이 하는 일이다.
- 강화 = 고리 한 바퀴 → 배부름 → 알. 균형 = 배고픔 · 다툼 · 먹이 감쇠. 둘 다 이름을 댈 수 있다.

## 5. 사전 예측과 대조군 (실행 전)

### 연구 — `experiments/run_cycle_markov.py` (N=20 시드, 짝지은 비교)
생성 경로는 Algorithm 1 과 같고 **음을 고르는 곳만** 바꾼다: 풀(공유 가중 합집합)에서 균등 추출 대신,
직전 음에서 **활성 고리의 향을 준 변**을 따라 다음 음을 고른다(없으면 원래 풀 추출).
지표: 음높이 JS(헤드라인과 같은 `eval_metrics`), **수평 음정 JS**(이웃 두 onset 사이 모든 음 쌍의 음정 분포),
**수직 음정 JS**(한 onset 안 음 쌍의 음정류 분포). OM = Tonnetz K=41 (τ=0.35 이진) 과 정본 DFT K=14 (per-cycle τ).
- **R1** 고리-Markov 는 수평 음정 JS 를 Algorithm 1 대비 **10% 이상** 낮춘다 (Tonnetz OM).
- **R2** 음높이 JS 는 Algorithm 1 대비 **±30% 안**에 머문다.
- **R3** 메커니즘 뺀 대조군 — **같은 고리 집합, 순회 순서만 무작위** — 는 R1 이득의 **절반 이상**을 잃는다.
- **R4** 향 뒤집기(역방향)는 순방향과 **5% 안**에서 같다 (시간 방향 효과는 작다고 본다 — 불확실).

### 페이지 — `tools/verify_tonnetz_lenia.mjs` (페이지와 같은 엔진 파일, 20시드)
- **V1** 고리를 같은 크기의 난수 고리로 바꾸면 부른 음의 음높이 분포 JS(원 고리 대비)가 **시드 간 잡음의 3배 이상**.
- **V2** 돌봄(8스텝마다 먹이) vs 방치: 3분 뒤 살아 있는 생명체 수가 돌봄 > 방치 (20/20 시드).
- **V3** 발자국 따라가기 on/off: on 에서 두 생명체의 가락 시차 상관(lag 8~64 최대값)이 off 보다 크다. 기대일 뿐, 틀려도 적는다.
- **V4** 원곡 두 손 리듬으로 깬 종달새·문어의 몸 점 배치가 §2.1 그림과 같다 (각도 분산: 종달새 ≈ 0, 문어 = 모듈당 1/32).

### 회로를 두 조건부의 교대로 보고 잰다 — V5·V6 (2026-09-29 사용자 지시, 실행 전)
이 회로(부른 음 → 고리 활성 → Algorithm 1 → 부른 음)는 **따로 만든 두 조건부를 번갈아 도는** 연쇄다
(활성도 = `overlap.py` 의 정의, 음 = `generation.py` 의 추출. 둘은 어떤 결합분포의 조건부로 유도된 게 아니다).
의사 깁스 표본기처럼 ① 수렴하나 ② 도달한 분포가 목표(hibari)에 가까운가 ③ 얼마나 빨리 섞이나를 **따로** 묻는다.
참고: 이성헌 세미나 「Uniform Ergodicity of a Continuous-Space Pseudo-Gibbs Sampler」(synchronous coupling),
Lindsten, Douc & Moulines (2015) *Uniform ergodicity of the Particle Gibbs sampler* — 정리 1 소수화
P(x,·) ≥ ε·φ(·) 가 출발점과 무관한 수렴 (1−ε)^k 를 준다. ⚠ 둘 다 연속 공간·가역 커널의 결과다. 우리 회로는 이산이고
**죽음(침묵)이 흡수 상태**라 그대로 옮겨지지 않는다 — 돌봄이 없으면 ①은 "모두 죽는다" 로 자명하게 참이 된다.

**결합 모드** (`coupled: true`): headStep 과 algorithm1 에 넘기는 난수를 (seed, S.t, cr.node) 로 새로 시드하고
생명체를 칸 번호 순으로 처리한다. 같은 시각·같은 칸 = 같은 난수 → 두 세계가 한 번 같아지면 계속 같다.
(공유 난수 하나를 쓰면 입력에 따라 소비 횟수가 달라져 첫 스텝부터 어긋난다 — NodePool 셔플과 같은 함정.)

**V5 입력 기억 시간 (③)** — 20시드, 640스텝(20모듈 ≈ 4분 51초), 두 세계는 시드·매개변수가 같고 처음 입력만 다르다.
- (a) 알 2개 vs 8개 — 같은 고정 칸 목록의 앞 2개 / 8개, 종은 번갈아, 높이 66 근처.
- (b) 알 4개, 같은 칸, **낮은 음역(52 근처) vs 높은 음역(81 근처)**. (바닥 칸은 음이름뿐이라 "낮은 칸" 은 알이 깨는 옥타브로 준다.)
- 조건 두 가지: **돌봄 없음** · **같은 돌봄**(8스텝마다 고정 순서의 hibari 칸 3곳에 먹이 1 — A·B 가 똑같이 받는다).
- 거리: 배치 차이 = (칸, 종, 음) 집합의 대칭차 크기 · JS(A,B) = 최근 32스텝에 부른 음높이 분포의 JS.
- 잡음 바닥 = 입력은 같고 시드만 다른 두 세계(결합 모드)의 JS. 시각마다 20쌍의 중앙값, 두 입력 중 큰 쪽.
- 기억 시간 = JS(A,B) 가 바닥 아래로 내려가 **끝까지 머무는** 첫 스텝(둘 다 침묵이면 아래로 친다). 끝내 못 내려가면 절단(>640).
  합쳐진 방식을 따로 센다: 둘 다 침묵 / 살아서 배치까지 같음 / 살아서 분포만 구별 불가.
- **대조군 — 균형 회로를 뺀 팔 (COST=0, 배고픔 없음).**

**V6 닫힌 고리가 도달하는 분포 (②)** — 같은 돌봄, 알 4개, 640스텝 중 처음 64스텝을 버리고 부른 음 전체의 음높이 JS 를

  거의 균등해서(엔트로피 0.974, 논문 §4.7.2) 아무 풀에서 뽑아도 가깝다. 이 지표는 메커니즘 검사로 약하다.
- (선택) 두 단계 민감도: 음 하나를 바꿨을 때 켜진 고리 수의 변화(해밍) × 고리 하나를 바꿨을 때 풀 분포의 변화(TV).

## 9. 2판 — 칸이 생명을 담는 오토마타 + intra·inter + 거꾸로 발견하기 (2026-09-29, 코드 전에 적는다)

사용자 지시 두 가지:
1. "automata 형태로 구현되길 바랐던 게 반영되진 않았지만" — 칸 자체가 국소 규칙으로 켜지고 꺼져 모양을 이뤄야 한다.
2. "inter intra 설계는 나만의 기여잖아. 그게 반영됐으면 좋겠고 … 우리가 직접 움직임을 조작함으로써 **역으로 이론을 발견**할 수도
   있도록 조작법 및 상호작용 방식이 정의되었으면 좋겠어."

### 9.1 원칙 — 앞으로(이론 → 움직임)와 거꾸로(움직임 → 이론)가 **같은 식**을 쓴다
사용자의 식 `timeflow_weight = intra + rate × inter` (한 손 안의 흐름 + rate × 두 손 사이의 흐름, lag 1)는
PH 가 보는 거리 행렬을 만든다. rate 를 0 → 1.5 로 쓸면 고리가 태어나고 죽는다 — **vineyard** 다
(Cohen-Steiner·Edelsbrunner·Morozov 2006, 저장소에 추가된 논문). 실측(정본 경로 재계산, `tonnetz.json` vines):
- 41개 중 **13개는 rate = 0 에서만** 있다 — 두 손이 서로를 전혀 듣지 않을 때만. rate 0.01 에서 한꺼번에 사라진다.
- **8개는 0.01~1.5 전 구간**에서 산다. 나머지 20개는 결합의 특정 구간에서 태어나고 죽는다(예: 0.74~1.33 → 1.14~1.33 → 1.34~1.5).
→ **2판의 손짓 = rate 를 움직이는 일.** 종달새(오른손)와 문어(왼손) 사이의 거리가 rate 다 — 멀면 0(각자 제 흐름), 붙이면 1.5.
  생명체를 옮기는 것이 곧 filtration 매개변수를 쓸어 보는 것이고, 그때 들리고 보이는 고리가 그 rate 의 hibari 고리다.

### 9.2 매질 (칸 = 생명)
- 432칸 Tonnetz 토러스(주기 (0,18)·(24,−12)), 칸마다 hibari 음 하나(음역 지형: y 에 따라 낮음→높음→낮음, 높이 z = 그 음높이).
- 확률 Greenberg–Hastings: 쉼 → 켜짐 → 불응 6스텝 → 쉼 (한 바퀴 8스텝 = 한 마디).
  쉬는 칸이 켜질 입력 = Σ 켜진 이웃의 **전도** c(음 a, 음 b; rate) + 자극. 켜질 확률 = σ(STEEP·(입력 − θ − 피로)).
- **전도 c = PH 가 그 rate 에서 보는 두 음의 거리를 뒤집은 것** (가까운 음끼리 잘 통한다) — `dist_grid`, rate 0.1 간격을 선형 보간.
  + 지금 **켜져 있고 그 rate 에 살아 있는** 고리의 변이면 가산점. 검은 건반 칸(소리 없음)은 약하게 통한다.
- 전체가 **확률 셀룰러 오토마타 = 배치 위의 Markov 연쇄**. 결합 모드에서는 칸마다 (seed, t, 칸) 균등 난수.

### 9.3 생명체 (파도의 원천) — 두 손
- **종달새 = 오른손**: 누르면 생기는 박동원. 제 모듈 **32** 안에서 8스텝마다 한 번, 제 칸과 이웃 6칸을 켠다 → 동심 파문.
- **문어 = 왼손**: 그으면 생기는 회전 원천. 제 모듈 **33** 안에서 8스텝마다 한 방향으로만 켜고 방향을 한 칸씩 돌린다
  → 한쪽 끝이 열린 파도들이 말려 나선 팔이 된다. 32·33 이라 둘의 박이 모듈마다 한 칸씩 어긋난다(hibari 의 위상 어긋남).
- 목소리: 생명체마다 **제 손의 리듬**(32 고리 / 33 고리의 onset 수)으로 운다. 음은 제 주변(격자 3걸음 안) 켜진 칸의 음 →
  고리 활성도(overlap.py 연속 정의, **그 순간** 켜진 음 — 1판 V6 의 교훈) → τ → 그 rate 에 살아 있는 고리만 → 한 행 → **Algorithm 1**.

### 9.4 거꾸로 발견하기 — 바코드를 손으로 채운다
- 화면 아래 가는 띠 = hibari 의 H₁ 바코드(가로 = rate 0~1.5, 막대 = 그 고리가 사는 rate 구간). 지금 rate 에 세로선.
- 어떤 목소리의 행에서 고리가 켜지면 그 막대의 **지금 rate 칸이 채워진다**. 플레이어는 두 손을 옮기며 rate 를 오가고,
  hibari 의 vineyard 를 제 손으로 복원한다. 찾은 칸은 이 브라우저에 남는다(localStorage — 다시 와도 이어서).
- 글자는 없다. 채워지는 막대가 곧 이론이다.

### 9.5 되먹임 한 쌍
- 강화: 켜진 음 → 켜진 고리 → 그 고리 변의 전도 가산 → 그 음들이 더 잘 켜진다.
- 균형: 불응기(한 마디에 한 번) + 피로(켤 때마다 쌓이고 천천히 풀린다) + 생명체의 수명(누르면 다시 찬다).

### 9.6 센서
1. 왜 내일 또 오나 — 아직 못 채운 막대가 있으니까, 두 손을 붙였다 떼는 게 소리로 재미있으니까. 찾은 게 남는다.
2. 첫 조작 글자 — "눌러서 깨우세요" (8자). 3. 누름 → 소리 즉시. 4. 손잡이 없음 — 거리가 rate 다.

## 10. 3판 — 살아 있는 격자 (2026-09-29, 코드 전에 적는다)

사용자 판정(2판): "피로를 세게 하자. 그리고 원하던 오토마타 형식이 아니야. 일단 분명한 건 **음악 자체는 듣기 좋아.**
하지만 개입을 통해 상호작용하는 방식이 직관적이지 않아. 마우스밖에 누를 수 없고 키보드로 더 적극적인 상호작용은 제한되잖아."
그리고 물음: "우리 설계에 '상태', '갱신 규칙'은 어떻게 반영돼 있나" · "JS 가 신뢰할 만한 지표가 아니었다고 계산되지 않았었어?"

### 10.1 무엇이 오토마타가 아니었나
| 판 | 상태 | 갱신 규칙 | 생명체 |
|---|---|---|---|
| 1판 | 칸: 먹이·발자국 (확산·감쇠) | 칸: 이웃 평균으로 퍼지고 줄어든다 | **칸 밖**의 행위자 — 머리·고리·기운을 가진 물체가 칸 위를 옮겨 다녔다 |
| 2판 | 칸: φ(쉼·켜짐·불응 6) + 피로 | 켜진 이웃의 전도 합 ≥ 문턱이면 켜질 확률이 오른다 | **칸 밖**의 원천 — 파도를 쏘는 박동원. 파도는 칸의 규칙이었지만 생명체는 아니었다 |
| **3판** | 칸: **A(생명) · F(피로)**, 손마다 | **A ← A + (G(K∗A) + 비옥도 + 먹이 − κF)/T** (Lenia) | **칸의 켜짐 자체** — 오비움처럼 스스로 모양을 지키며 미끄러진다 |

⚠ 탐색 결과: **칸 하나 = 음 하나인 굵은 격자(648칸)에서는 Lenia 생명체가 살지 못한다** — 반경 2·3, 매개변수 180개씩, 전부 죽거나 번졌다(반경 2: 죽음 60 · 번짐 120, 반경 3: 63 · 117; 탐색 격자 36×18).
Lenia 원래대로 **고운 격자(256 × 128)**에 생명체가 살고, Tonnetz 는 그 위의 지도(고운 칸마다 그 자리의 Tonnetz 칸 → 음)다.
오비움(R=13, μ=0.15, σ=0.015, T=10)은 이 격자(가로·세로 칸 크기 13% 비등방)에서도 질량 ≈61 로 미끄러진다.

### 10.2 intra · inter — 갱신 규칙 안에
음 u 의 비옥도_c = Σ_v m_c(v)·intra_c(v,u) + rate·Σ_v m_c'(v)·inter(v,u). m_c(v) = 손 c 가 지금 음 v 의 칸들에 가진 생명의 양.
intra_c = 그 손의 화음 전이(`compute_intra_weights`, lag 1), inter = 두 손 사이(`compute_inter_weights`, lag 1) — `refine_connectedness_fast` 로
음 단위, 최댓값 1. 실측: 오른손·왼손 intra 상관 **0.99**(같은 재료), intra·inter 상관 **0.15**, 0 아닌 쌍 intra 52% vs inter **100%**.
→ rate 0: 생명체는 **제 손의 다음 음** 쪽으로 자란다(성긴 길). rate 가 오르면 다른 손이 이어 주는 넓은 곳으로.

### 10.3 손과 키보드
- **←↑→↓ 종달새를 그쪽으로 · W A S D 문어를 그쪽으로** — 누르고 있는 동안 머리 옆에 먹이를 두어 돌린다.
  (탐색: 머리 기준 (−hy, hx) 쪽 먹이 → 각도가 준다 = 먹이의 **반대**로 돈다. 먹이 0.3 에서 350스텝에 한 바퀴, 0.6 은 터진다.)
- **Q E** rate 내리기·올리기 (0.1씩). **1 2** 종달새·문어 하나 더(비어 있는 곳에).
- 마우스: 누르기 종달새 · Shift/오른쪽 누르기 문어 · 끌기 먹이 길. 터치: 누르기 · 길게 누르기(문어) · 끌기 · rate ± 단추.
- 문어는 몰지 않으면 약하게 한쪽으로 돈다(왼손의 어긋남 = 길의 휘어짐).

### 10.4 지표 — JS 대신 MI (사용자 지적)
JS(원곡과의 음높이 분포 거리)는 **닮음**을 잰다. 08-15 블라인드 A/B 에서 지표 예측이 4쌍 중 1쌍만 맞았고(N=1), 08-31 에 목표가
"원곡에 가까운가" 에서 **"내 조작이 들리고 방향이 맞는가"** 로 바뀌었으며, 09-05 감사는 그 질문은 **I(조작 ; 출력)** 으로 재야 한다고
결론냈다(`run_knob_mi.py` — 순열 귀무를 뺀 MI_adj, 방향 = Spearman ρ, 천장 = 같은 경로로 통과시킨 완벽 계단).
→ 1판 V6·2판 W5 의 JS 는 "분포가 원곡에서 얼마나 떨어졌나" 의 **서술**일 뿐 좋고 나쁨의 근거가 아니다. 2판 W4(JS 로 잰 메커니즘 검사)는
지표의 **종류**가 틀렸다. 3판은 MI 로 잰다.

### 10.5 사전 예측 (`tools/verify_life.mjs` + `experiments/run_life_mi.py`, 20시드)
- **X1 몰기가 먹힌다**: 방향 4개(→↓←↑) × 20시드, 몰기 시작 20박 뒤부터 30박 동안의 이동 방향(8구간) — MI_adj/천장 ≥ **0.5**, 순열 p < 0.01.
  이동 방향이 목표 ±45° 안인 비율 ≥ **70%**.
- **X2 rate 가 들린다**: rate 0 · 0.5 · 1.0 · 1.5 × 20시드, 생명체 둘을 같은 자리에서 5분 — 찾은 고리 수에 대해 MI_adj p < 0.01,
  방향 |ρ| ≥ 0.5 (부호는 모른다). 음높이 평균에 대해서는 MI_adj 가 귀무와 구별되지 않는다(방향 없음)고 예측한다.
- **X3 intra·inter 가 움직임에 닿는다**: 실제 가중치 vs 음 쌍을 섞은 가중치 — 생명체가 지나간 Tonnetz 칸 음의 분포(12 음이름)에 대해
  조건(실제/섞음) ↔ 출력 MI_adj p < 0.05. (2판 W4 는 전도가 소리에 닿지 않았다. 여기서는 비옥도가 **움직임**에 닿는지 본다.)
- **X4 균형(강한 피로)**: 방치하면 20/20 이 **5분 안에** 사그라진다. 60초마다 몰아 주면 ≥ 16/20 이 5분을 산다.

### 10.6 착수 뒤 설계 수정 (예측 X1~X4 를 돌리기 **전**, 탐색 — 전부 scratchpad 스크립트, JSON 없음)
- **몰기**: 처음 설계(머리 옆에 **질량**을 더한다)는 먹이의 **반대**로 돌았다 — 질량을 더하면 퍼텐셜이 μ+σ 를 넘어 그쪽이 줄어든다(밀어냄).
  반면 **성장 가산**(비옥도·끌기 먹이 방식)은 끌어당긴다. 비교 (방향 4 × 시드 3, 30박마다 방향을 바꾸는 가혹 시험, 생존 / ±45° 적중):
  옆 질량 0.28 = 9/12 · 64% · 옆 질량 0.12 = 12/12 · 17% · 뒤에서 밀기 = 12/12 · 17% · 앞쪽 끌어당김 0.2 = 12/12 · 33%(둘로 갈림 — 목표가 앞이면 0~15°,
  옆·뒤면 무반응) · **옆 끌어당김 0.35 = 8/12 · 73%** · 옆 끌어당김 0.15 = 12/12 · 33%.
  → 채택: **옆 끌어당김, 누르면 0.15 에서 약 7초에 걸쳐 0.35 로, 질량이 48 아래로 내려가면 쉰다** = 11/12 · 58%.
  또 하나: 막 태어난 생명체를 곧바로 몰면 무너진다(맨 오비움도 3개 중 2개) → 태어난 뒤 12박은 몰기를 받지 않는다.
  교훈: **Lenia 생명체를 빨리 돌리는 것 자체가 불안정하다.** 몰기는 느리다(90° 에 약 10초). 그래서 **음 부르기**를 더했다 —
  Z X C V B N M(도~시)을 누르면 그 음이 곧바로 울리고, 생명체 가까운 그 음 칸이 약하게(0.15) 끌어당긴다. 방향이 아니라 **화성으로** 부른다.
- **강한 피로**: 피로가 몸 아래서 빨리 쌓이면(up ≥ 0.03, κ 0.3) 방치한 생명체는 죽지만(24~488박) **몰아 준 쪽이 더 빨리 죽었다**(10~76박) — 이 두 범위는 콘솔 출력만 남았다(미저장).
  질량 몰기와 겹칠 때였다. 양분 규칙(먹으면 줄고 천천히 찬다)도 같은 모양이었다(돌봄 7~35박). 느린 피로(up ≤ 0.015)는 방치해도 3000스텝을 버틴다.
  → 끌어당김 몰기로 바꾼 뒤 다시 쟀다: 자리 피로 κ 0.3 · up 0.04 에서 방치 17·660·437박 vs **돌봄 17·56·46박** — 여전히 돌봄이 더 빨리 죽는다.
  원인: 몰면 생명체가 돌면서 **제 발자국(자리에 남은 피로)** 위로 들어간다. 자리 피로는 몰기와 본질적으로 부딪힌다.
- **그래서 센 피로를 자리에서 몸으로 옮겼다 = 나이 G.** 칸마다 몸 안 이웃의 나이를 물려받고(3×3, 생명 가중) 스텝마다 AGE 만큼 늘어난다.
  갱신 규칙에 −KAGE·G. 먹이·끌어당김(몰기·부르기)이 닿은 칸은 스텝마다 YOUNG(3%)만큼 젊어진다. 생명이 떠난 칸은 나이를 잊는다(×0.9).
  여전히 **국소 규칙**이다(이웃 3×3 만 본다). 자리 피로는 약하게(κ 0.12 · up 0.008) 발자국으로만 남긴다.
  ⚠ 첫 구현은 나이가 **새었다** — 가장자리(생명 < 0.3, 막 켜진 칸이라 나이가 낮다)까지 평균에 넣으니 몸의 나이가 ≈0.005 에서 멈췄다(평형).
  몸의 **속**(생명 ≥ 0.3)끼리만 물려주게 고친 뒤: 방치한 생명체(시드 5)의 속 나이가 60박마다 평균 0.037 씩 늘어(새지 않았다면 0.046)
  **360박(≈2.7분)에 사그라졌다** (300박 나이 0.185 · 질량 60 → 360박 질량 1, 무너짐은 나이 0.19~0.22 사이).
- **고친 뒤 방치 vs 돌봄** (시드 1~3, 돌봄 = 132박(60초)마다 40박 몰기; scratchpad `neglect4.mjs`, 탐색 3시드):
  AGE 0.00019 → 방치 326·217·451박 | 돌봄 **660·660·660** (5분 생존) · AGE 0.00014 → 방치 502·337·537 | 돌봄 660·660·660.
  **여기서 처음으로 돌봄이 방치보다 오래 산다.** 사용자가 "세게" 를 원했으므로 AGE 0.00019 (방치 1.6~3.4분)를 쓴다. 이 값으로 X1~X4 를 돌린다.
- 페이지: 나이는 **색**으로 보인다 — 늙을수록 금빛·산호빛이 잿빛으로 바래고(나이 0.2 에서 다 바랜다), 돌보면 다시 빛난다.

**비옥도**: 짝지은 설계(같은 시드·같은 자리, 가중치만 바꿈)로 보니 전역 0.06 에서도 실제↔섞음 경로가 1분 뒤 중앙 2.6 벌어진다 —

**"칸을 옮길 때 hibari 의 전이가 높은 이웃으로 가나"** — 전이 점수 = 옮겨 간 칸의 W(앞 음 → 새 음) − 앞 칸 6-이웃 평균 W(실제 intra_right).
8시드 짝, 264박: 전역 0.06 실제 −0.0001 · 섞음 −0.0037 · 끔 −0.0007 (효과 없음) / 전역 0.15 실제 +0.0034 (섞음보다 큼 7/8, 끔보다 5/8) /
**국소 0.1 실제 +0.0118 · 섞음 −0.0035 · 끔 −0.0007 (끔보다 큼 7/8, 섞음보다 8/8)** / 국소 0.2 −0.0027 (나빠짐, 생존 6/8).
원인: intra 는 **같은 음 반복**(대각 평균 0.20 vs 비대각 0.09)이 가장 커서, 전역식은 생명체가 **이미 있는 칸**을 가장 비옥하게 만든다.
국소식은 칸 i 의 비옥도 = Σ_{j ∈ 6-이웃(i)} M_c(j)·intra_c(음 j → 음 i) + rate·M_c'(j)·inter(음 j → 음 i) (자기 칸 제외) — **Tonnetz 이웃 규칙**이다.
(inter 는 다른 손이 **이웃 칸에 있을 때만** 닿는다 — 두 생명체가 가까워야 서로의 다음 음 쪽으로 자란다.)

**두 회차에 걸쳐 남는 것**
- 몰기는 먹힌다 — 두 회차 모두 순열 p ≤ 0.00025, ±45° 91.3%(끌기 0.35) · 72.5%(0.30). 힘을 줄이면 날카로움(MI 비율 0.74 → 0.43)이 준다.
- 돌봄과 방치는 갈린다 — 5분 생존 돌봄 14/20 · 15/20 vs 방치 1/20 · 2/20. 그러나 두 회차 모두 사전 문턱은 못 넘었다.
- rate 는 **그 rate 에 살아 있는 고리 집합(바코드)**을 바꾸고 그것이 들린다 — 0.5 ↔ 1.0 사이 계단 하나(울린 음높이 약 −1.2). 찾은 고리 수는 그 집합에 포화한다
  (2회차 순열 p ≤ 0.00025, 1회차 X2 는 무효 자료라 채점하지 않았다). **둘 다 생명체 행동이 아니라 filtration 이 소리에 닿는 통로다**(§10.11).
**남지 않는 것**
- 비옥도가 생명체를 hibari 의 전이 쪽으로 걷게 한다는 주장 — 점추정의 부호만 맞고 판별할 수 없었으며(Holm 0.064 · 0.077, 검정력 0.47 · 0.28),
  **대가로 생존을 깎는다**(2분 13/20 vs 비옥도 0 에서 20/20; 2회차 돌봄 죽음 5건도 비옥도 과성장 — §10.11).
  → 페이지 기본값을 **비옥도 끔(v3.2)**으로 바꿨다. intra·inter 는 rate → 바코드 → 소리 통로로 닿는다. 비옥도를 다시 켜려면 국소 정규화·과성장 방지 먼저(§10.11).

### 10.11 적대적 검토 (2026-09-30, 2회차 뒤) — 해석 정정
검토자가 원자료를 비트 단위로 재현한 뒤 분해했다(재현 스크립트 scratchpad `adv/`). 위 §10.10 의 해석 중 아래를 고친다.
- **(치명) X2b 음높이 변화는 생명체가 아니라 바코드다.** 비옥도용 rate 와 고리 마스크용 rate 를 떼어 재면(10시드, 0.5 ↔ 1.0) 마스크만 바꿀 때
  −1.33 / −1.22 (10/10 음수, p = 4.4e-8), CA 만 바꿀 때 +0.06 / +0.17 (p = 0.79 / 0.46). 생명체 없이 vines 만으로 계산해도 65.12 → 63.77
  (관측 65.02 → 63.78). 계단은 0.5 ↔ 1.0 사이 하나뿐이다(0 → 0.5 p = 0.42, 1.0 → 1.5 p = 0.44). 0.73~0.92 에서 고음 고리 8·12 가 지고 저음 고리 13 이 난다.
  → **"rate 가 방향 있게 음높이를 민다" 가 아니라 "이 바코드의 계단 하나가 들린다"** — 사용자의 intra + rate·inter 가 filtration 으로 소리에 닿는 통로이긴 하다.
- **(치명) 찾은 고리 수는 동어반복이다.** 10/10 시드가 같은 집합을 찾고 24~116박 안에 그 rate 에서 닿을 수 있는 수(0.5: 9, 1.0: 10)에 포화한다.
  MI 비율 1.01 은 구간 수 불일치(출력 고유값 5 → 5구간, 천장 8구간) 탓이다 — 맞추면 0.945.
- **(중요) 2회차 비옥도(FLOCAL)는 국소가 아니다.** `fe3 /= mx3` 가 격자 전체의 최댓값으로 나눈다 → 두 손이 닿지 않아도 한 손의 비옥도가 다른 손 위치와 rate 에
  달려 있다(문어 몸 위 비옥도 rate 0 / 0.5 / 1 / 1.5 에서 0.102 / 0.032 / 0.016 / 0.011). §10.9 의 "이웃에 있을 때만 닿는다" 는 틀렸다.
- **(중요) 2회차 돌봄 죽음 5건은 비옥도 과성장이다** — 죽을 때 몸 나이 ≤ 0.027, 판 전체 최고도 0.069~0.085(방치는 0.14~0.20). 모두 포화 칸 11~17개 뒤 8스텝 안에 무너졌고
  2건(657·520박)은 몰기가 꺼진 동안이었다. 같은 시드·같은 몰기에서 비옥도 0 이면 5/5 가 산다. 방치 죽음은 나이다(비옥도 0 이어도 5/5 죽고, 나이 0 이면 4/4 산다).
  몰기가 없는 X3b 에서도 2분 생존 13/20 vs 20/20 (p = 0.0083). 혼돈계의 반사실이라 조건부 근거다.
  → §10.9 의 "과식 죽음은 끌기의 세기가 원인" 은 **1회차 엔진(전역 비옥도 0.06)에서만** 성립한다. 공통 계급: **몸 아래 더하는 성장 가산은 무엇이든 속을 채워 무너뜨린다.**
- **(중요) X3b 는 편향은 없지만 판별할 수 없었다** — 관측 효과가 참이어도 검정력 0.47 / 0.28, 80% 에 35 · 53쌍 필요. 점수가 규칙이 더하는 Σ M·W 와 같은 꼴이라
  통과해도 독립 증거가 아니다. → 점추정의 부호만 예측과 같다.
- (경미) X1b: 원을 자르는 자리만 바꿔도 MI 비율 0.43~0.49 (목표 중심 섹터 0.505), 적중률 Wilson 구간 [0.62, 0.81] — 두 문턱 모두 경계. 0.74 → 0.43 은 끌기·비옥도·각도가
  한꺼번에 바뀐 비교다.
- (경미) 각도 옮김 2.266 ≈ 5 × 1.7 (mod 2π) → X3b 20/20 이 1회차 시드와 2.8~5.7° 안, 11/20 이 비옥도 탐색과 5.7° 안에 놓였다. 20점이 원을 채우니 각도만으로는
  독립 초기 조건을 만들 수 없다 → **자리도 옮겨야 한다.**
- 유지: params 는 v3.1, 섞음 팔은 FLOCAL 경로에도 적용, X1 토러스 수정 적용(jumps 0/80), X1 천장 자체는 공정, Holm 계산 맞음.

**결정**: 비옥도는 지금 **돌봄을 벌하는 경로**다(CLAUDE.md "균형 회로가 돌봄을 벌하지 않는지"). 페이지 기본값을 **v3.2 = v3.1 + 비옥도 0** 으로 바꾼다.
사용자의 intra·inter 는 페이지에서 rate → 바코드(그 rate 에 살아 있는 고리) → 소리 통로로 남는다. 비옥도 통로는 국소 정규화·과성장 방지·n ≥ 55 사전등록 뒤에 다시 연다.

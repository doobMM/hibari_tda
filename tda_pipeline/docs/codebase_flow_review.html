Stage 2A

5. 가중치 단계는 “자주 같이 움직인 것일수록 가까운 음”이라는 그래프를 만듭니다

compute_intra_weights

한 악기 내부에서 chord A 다음에 chord B가 나온 횟수를 셉니다.

compute_inter_weights_decayed

두 악기 사이 lag 1부터 4까지를 감쇄 가중치로 합칩니다. 현재 비중은 0.60, 0.30, 0.08, 0.02입니다.

compute_simul_weights

동시 발음에서 같은 악기 내부 조합과 두 악기 차집합 간 연결을 따로 셉니다.

refine_connectedness_fast

chord-level weight를 note-level weight로 분해합니다. 확장 행렬 E를 써서 E.T @ W @ E 형태로 계산합니다.

chord weight W
 -> to_upper_triangular(W)
 -> refine_connectedness_fast(W, notes_dict)
 -> weight_to_distance(1 / weight, out_of_reach for zero)
 -> symmetrize_upper_to_full(D)
중요한 버그픽스가 들어간 파일입니다. 기존에는 upper triangular 변환 후 refine하면서 chord 번호와 note 번호 방향이 엇갈릴 때 연결이 누락될 수 있었습니다. 현재는 W + W.T로 대칭화한 뒤 note 단위로 refine합니다.

Stage 2B

6. 음악적 거리 함수는 빈도 그래프에 화성적 의미를 주입하는 플러그인입니다

거리계산 방식의미주의점
frequency가중치의 역수곡 안에서 자주 이어진 음은 가까움음악 이론은 직접 반영하지 않음
tonnetzpitch class를 장/단3도, 5도 그래프에서 BFS화성적으로 가까운 음을 가깝게 봄옥타브와 duration은 별도 가중치로 더함

dftpitch class indicator의 Fourier 계수 L2pitch class의 순환 구조를 연속 공간에서 비교단일 pitch class DFT만으로는 구분력이 제한될 수 있음

Stage 2C

7. Persistent Homology는 거리 행렬에서 오래 살아남는 cycle을 찾습니다

generate_barcode_numpy

기존 professor.py의 pHcol 스타일 알고리즘을 numpy와 sparse column 표현으로 최적화한 버전입니다. generator 문자열까지 기존 형식에 맞춥니다.

generate_barcode_ripser

ripser가 설치되어 있으면 C++ 기반 계산을 사용합니다. birth/death는 빠르지만 cycle representative는 death edge와 BFS로 근사 추출합니다.

1

filtration 값

거리 행렬의 고유 양수값을 simplex 등장 시점으로 씁니다.

2

VR complex

edge, triangle, higher simplex의 diameter를 계산합니다.

3

boundary matrix

simplex의 face 관계로 경계 행렬을 만듭니다.

4

column reduction

pivot을 줄여 birth/death interval을 뽑습니다.

5

cycle parse

overlap.group_rBD_by_homology가 generator 문자열을 cycle key로 바꿉니다.

ripser 경로의 generator는 기존 pHcol generator와 완전히 같은 edge 조합이 아닐 수 있습니다. 코드상 “동치인 cycle을 표현”한다고 되어 있으므로, cycle 구성 자체가 논문 수치에 쓰일 때는 테스트 비교가 필요합니다.

8. 중첩행렬은 “어느 시점에 어떤 cycle이 켜져 있었는가”를 기록한 생성 seed입니다

1

cycle labeling

label_cycles_from_persistence가 cycle key를 열 번호로 정렬합니다.

2

note-time

각 시점에 활성 note label set을 T x N DataFrame으로 만듭니다.

3

activation

cycle 안 note가 현재 시점에 켜졌는지 계산합니다.

4

scale/threshold

연속 활성 구간 또는 per-cycle threshold로 T x K 이진 행렬을 만듭니다.

binary activation

cycle note 중 하나라도 활성화되면 1입니다. 단순하고 빠릅니다.

continuous activation

활성 note 비율에 희귀도 가중치를 곱합니다. 드문 note가 켜질수록 값이 커집니다.

per-cycle tau

cycle마다 다른 임계값을 적용합니다. 단일 threshold보다 섬세하지만 tau 목록 길이와 열 순서가 맞아야 합니다.

scale search

기존 binary 방식은 cycle 길이를 초기 scale로 두고 연속 run의 ON 비율을 threshold 범위에 맞춥니다.

Stage 4A

9. Algorithm 1은 overlap이 켜진 cycle의 note pool에서 확률적으로 음을 뽑습니다

활성 cycle이 있을 때

CycleSetManager.get_intersect_nodes가 활성 cycle들의 구성 note를 빈도 기반 pool로 만듭니다. 정확히 수학적 교집합이라기보다, 활성 cycle 안에 등장한 vertex를 빈도 카운트로 모은 pool에 가깝습니다.

활성 cycle이 없을 때

이웃 시점의 활성 cycle 합집합을 피해서 샘플링합니다. 즉 구조가 비어 있는 칸은 주변 cycle과 겹치지 않게 채우려는 경향이 있습니다.

1

NodePool

원곡 note 빈도를 반복 pool로 만들고 temperature로 평탄화합니다.

2

Chord height

각 시점에서 몇 개 note를 onset할지 패턴을 받습니다.

3

Sampling

overlap 행의 활성 여부에 따라 cycle pool 또는 전체 pool에서 뽑습니다.

4

Sustain 반영

긴 note가 지속되는 동안 미래 시점의 inst_len을 줄입니다.

5

NodePool.label_to_note_info는 입력 label을 0-index로 보고 내부에서 label + 1을 찾습니다. CycleSetManager의 cycle vertex도 0-index라는 전제와 맞물려 있으니, note label 계약 변경 시 가장 먼저 깨질 수 있습니다.

Algorithmic Peculiarities

13. 코드 리뷰에서 눈여겨볼 특이사항과 실패 가능 지점입니다

1

1-index와 0-index 혼재.
notes_label은 1-index, cycle vertex와 모델 output은 0-index로 쓰이는 구간이 많습니다.

2

solo note 수와 solo timepoint는 다릅니다.
hibari에서는 solo_notes=59, solo_timepoints=32가 서로 다른 개념입니다.

3

auto_detect는 완전 자동이 아닙니다.
solo 구조는 fallback 사용 권장이라고 코드가 말합니다.

4

refine_connectedness는 연구 수치에 직접 영향.
현재는 대칭화 후 refine하는 post-bugfix 경로입니다.

5

ripser generator는 근사 대표 cycle.
birth/death 일치와 generator 동치성은 다른 문제입니다.

6

continuous activation은 희귀도 가중.
단순한 활성 note 비율이 아니라 cycle 등장 빈도 역수 가중이 들어갑니다.

7

Algorithm 1의 sustain 차감이 note 수를 줄입니다.
chord-height 합과 실제 onset 수가 같지 않습니다.

# 위상 손실 결합 디퓨전 — hibari 중첩행렬 생성 (2026-08)

> `docs/research_next_algorithms_2026.md` §1(최우선 후보, TopoDiffusionNet / ICLR 2025)의 실제 접목 기록.
> 선행 실패(`project_om_diffusion_negative_0621`, 커밋 54e7878)에 대한 직접 대응.

---

## 1. 무엇을 고치려 했는가

2026-06-21 의 OM 디퓨전 실험은 negative 였다. 실패는 두 숫자로 요약된다.

| 지표 | 원곡(REAL) | MLP-DDPM | 진단 |
|---|---|---|---|
| 활성 셀 수 (840셀 중) | 139.0 | **418.2** | 밀도 3배 과밀 |
| 시간축 autocorr | 0.8135 | **0.5038** | 시간 구조 붕괴 |
| cycle별 활성 프로파일 JS | — | 0.03037 | 14개 cycle이 전부 ≈0.5로 균질화 |

세 번째 줄이 결정적이다. MLP-DDPM 의 cycle별 프로파일은 `[0.480, 0.499, 0.492, …, 0.501]`
— **모든 cycle 이 거의 정확히 0.5**. 이는 "cycle 마다 다른 리듬으로 켜진다"는 hibari 의 구조를
전혀 배우지 못하고 사실상 균일 노이즈를 뱉었다는 뜻이다.

원인은 아키텍처였다. 60×14 격자를 **840차원 벡터로 평면화**해 MLP 에 넣으면,
"셀 (t, c) 와 셀 (t+1, c) 가 이웃"이라는 사실이 모델에 전혀 전달되지 않는다.
시간축은 그저 840개 좌표 중 아무 축이 된다.

## 2. 두 갈래 대응

### 2.1 아키텍처 — 평면화를 없앤다

중첩행렬을 **K=14 채널 × T=60 시간**의 다변량 시계열로 본다. 디노이저는 시간축 1D conv U-Net:

```
(B,14,T) → Conv1d(14→48) → ResBlock → ↓2 → ResBlock(96) → ↓2
         → mid ResBlock ×2 → ↑2 (skip) → ↑2 (skip) → Conv1d(48→14)
```

각 ResBlock 은 커널 5의 Conv1d 두 개 + 시간스텝 임베딩을 FiLM(scale·shift)으로 주입.
773,342 파라미터 — 학습 창이 515개뿐이므로 의도적으로 작게 잡았다.

### 2.2 위상 손실 — 1차원 cubical persistence 의 폐형식

TopoDiffusionNet 은 매 디노이징 스텝에서 예측된 x̂₀ 에 persistent homology 를 계산해
Betti 수를 목표에 맞추는 손실을 건다. 원 논문은 256×256(65,536픽셀) 이미지라
스텝마다 PH 를 돌리는 비용이 크고, 연구 조사 문서도 이를 리스크로 적었다.

**우리 문제에서는 그 비용이 0 이다.** 음악적으로 의미 있는 위상은
"cycle 하나가 몇 번, 얼마나 길게 켜지는가" — 즉 **각 열(cycle)의 시간축 0차원 호몰로지**다.
그리고 1차원 신호의 superlevel-set H₀ persistence 총합은 폐형식을 갖는다:

$$\sum_i \mathrm{pers}(H_0\text{-feature}_i) \;=\; \text{총 상승변동} \;=\; \sum_t \mathrm{ReLU}\big(x[t] - x[t-1]\big),\qquad x[-1] := 0$$

**전제 두 개를 명시한다** — 이 등식은 "1차원 신호 일반"에 성립하지 않는다.
(1) **x ≥ 0**, (2) filtration 을 **level 0 에서 절단**하는 규약 — essential class 의 death 를
−∞ 가 아니라 0 으로 두는 상대 persistence H₀(X, {x ≤ 0}). 표준 superlevel PH 는
essential bar 가 무한대라 좌변이 발산하므로, 이 규약 없이는 등식이 성립하지 않는다.
런타임에서는 두 전제가 보장된다 — `pred_x0` 이 [-1,1] 로 클램프한 뒤 x01=(x+1)/2 이므로
x ∈ [0,1] 이고, 원본 OM 도 `np.clip(..., 0, 1)` 을 거친다.

이진 신호에서 이 값은 **활성 구간의 개수와 정확히 같다** (신호 끝에서 잘리는 구간도
포함 — 폐형식은 하강이 아니라 **상승** 에지를 세기 때문이다).

ε-게이트 `ReLU(rise − ε)/(1−ε)` 의 의미는 **정확히 적어야 한다.** 게이트가 걸리는
대상은 한 feature 의 persistence 가 아니라 **한 스텝의 상승 증분** rise_t 다.
- **이진 regime**: rise_t ∈ {0,1} 이므로 게이트는 곧 "persistence ≤ ε 인 feature 제거"와
  같아진다. 실제 hibari OM 을 τ=0.5 로 이진화하면 7210개 채널 전부에서
  게이트값 = #(persistence > ε) 로 **100% 일치**한다.
- **연속 regime**: 완만한 경사로 여러 스텝에 걸쳐 올라가는 큰 feature 는 각 스텝의
  증분이 작아 **함께 깎인다**(예: 30스텝 선형 램프는 참 feature 1개인데 게이트값 0).
  따라서 "유의한 feature 만 센다"는 TopoDiffusionNet 의 역할은 **이진 극한에서만**
  정확하고, 학습이 실제로 보는 연속 x̂₀ 에서는 근사다.

따라서 gudhi·cripser 같은 외부 PH 라이브러리 없이, **O(T)**, **정확히 미분 가능**하게
persistence 를 손실에 넣을 수 있다.

**검증** (`h0_total_persistence` 단위 테스트):

| 항목 | regime | 결과 |
|---|---|---|
| 폐형식 vs 브루트포스 1D superlevel PH (무작위 3000개) | 연속 | max\|차이\| = **3.55e-15** |
| 폐형식 vs 활성 구간 개수 (무작위 5000개, 끝 절단 포함) | 이진 | max\|차이\| = **0.0** |
| 실제 hibari 창 16개 평균 | **이진화본** | 폐형식 4.2232 / 검산 4.2232 |
| 실제 hibari 창 16개 평균 | **연속 원본** | ε=0.10 → 2.4139 / ε=0 → 3.6093 |
| 그래디언트 non-zero 비율 | 이진 | 3360셀 중 337셀 (약 11%) |
| 그래디언트 non-zero 비율 | **연속 — 학습이 실제로 보는 것** | 약 34~40% |

**주의** — 3행의 4.2232 는 **τ=0.5 로 이진화한** 입력의 값이다. 학습 손실은 연속값
x̂₀ / x₀ 위에서 돌고(데이터의 73.9%가 0/1 이 아니다), 연속 regime 의 실제 값은 2.4139 다.
"구간 수"라는 이름은 이진 행에만 맞고, 연속 행은 **"게이트 총 상승변동"** 으로 읽어야 한다.

마지막 두 줄이 이 손실의 성격을 보여준다. 그래디언트가 전 셀에 고루 흐르지 않고
**상승 에지와 그 직전 셀에 부호가 반대인 쌍으로** 흐른다 — 위상적으로 임계인 곳이다.
이것이 TopoDiffusionNet 의 "critical point 에서의 gradient" 를 1차원에서 구현한 형태다.
(비율은 regime 에 따라 다르다: 이진 약 11%, 연속 약 34~40%.)

### 2.3 손실 결합

$$L = L_{\text{simple}} + \bar\alpha_t\big[\lambda_{\text{topo}} L_{\text{topo}}(\hat x_0, x_0) + \lambda_{\text{dens}} L_{\text{dens}}(\hat x_0, x_0)\big]$$

- x̂₀ 는 예측된 ε 에서 역산 후 [-1,1] 클램프.
- ᾱ_t 가중 — 저노이즈 구간일수록 x̂₀ 가 의미 있으므로 그때 위상 제약을 강하게 건다.
- **원 논문과의 결정적 차이 — 조건부 vs 무조건부.** TopoDiffusionNet 은 목표 Betti 수 c 를
  *조건 입력*으로 받는 **조건부** 생성기이고, "c개 구멍을 갖는 마스크를 만든다"가 논문의
  핵심 기여다. 우리 학습은 조건이 없는 **무조건부** 생성이고, 목표 위상을 그 배치의
  실제 x₀ 에서 **자기지도로** 가져온다. 목표가 다르므로 이것은 TDN 의 재현이 아니라
  **손실 설계 아이디어의 이식**이다. (조건부 통제는 별도로 RePaint 로 얻었다 —
  `docs/motif_control_design.md`.)
- λ_topo = 0.30. **λ_dens 의 실효값은 30 이다** — 코드가 밀도 MSE 에 ×100 을 곱한 뒤
  0.30 을 곱하기 때문이다(밀도 오차는 위상 항보다 수치 스케일이 두 자릿수 작다).
  ε = 0.10.

## 3. 이진화 프로토콜 — 선행 실험의 자 문제

선행 실험은 REAL 을 **τ=0.5 임계값**으로, 생성물을 **밀도 일치**(Σp 개의 상위 셀만 ON)로
이진화했다. 그런데 연속 OM 의 평균 활성도는 0.2637 이므로 밀도 일치는
840 × 0.2637 ≈ 222 셀을 켜는 반면 τ=0.5 는 139 셀만 켠다.

**연속 분포를 완벽히 재현한 모델조차 밀도 일치 아래서는 REAL(139)에 도달할 수 없다** —
두 군을 다른 자로 잰 셈이다. (VAE 가 정확히 218 을 기록한 것이 이 자의 성질을 보여준다.)

그래서 본 실험은 두 자를 모두 보고한다.

- **`tau05`** — 학습 데이터와 동일한 자. **1차 판정 기준**.
- **`densmatch`** — 기존 기록과 직접 비교하기 위한 자.

MLP-DDPM 은 출력이 거의 균일 0.5 였으므로 τ=0.5 로 잘라도 절반이 켜진다.
**따라서 선행 negative 결론 자체는 이 재정의로 바뀌지 않는다.**

## 4. MultiDiffusion 장형 합성

T=60(약 27초)은 감상하기에 짧다. 창 하나로 학습한 모델에서 긴 OM 을 얻기 위해
MultiDiffusion(ICML 2023) 방식을 쓴다 — 매 디노이징 스텝에서 겹치는 창들
(stride 15)의 ε 예측을 Hann 창 가중으로 평균해 하나의 ε 로 융합한다.
**추가 학습 없이 길이만 확장된다.** T=240 → 약 1분 50초 (66 BPM, 8분음표 = 0.4545초).

## 5. 도중에 잡은 두 개의 버그 — 그리고 그것이 결론을 바꾸는가

결과를 적기 전에, 이 실험에서 나온 가장 중요한 발견 둘을 먼저 적는다.
둘 다 **선행 실험의 결론이 흔들릴 수 있는** 종류였기 때문이다.

### 5.1 x̂₀ 클리핑 누락 (샘플러)

사후평균 공식 자체는 Ho et al. 2020 eq.(7) 이지만, **매 스텝 x̂₀ 를 [-1,1] 로 자르는 것은
논문 본문이 아니라 저자 공개 구현·Improved DDPM(Nichol & Dhariwal 2021)·diffusers 의
`clip_sample` 관행이다.** 이 클리핑이 빠지면 200 스텝 동안 오차가 누적돼 샘플이
양 극단으로 포화된다. 실제로 그랬다.

| | 클리핑 없음 | 클리핑 있음 | 데이터 |
|---|---|---|---|
| 샘플 평균 | 0.4222 | **0.2662** | 0.2637 |
| 샘플 std | 0.4935 | 0.2226 | — |
| τ=0.5 활성비율 | 0.4333 | **0.1577** | 0.1578 |

포화된 출력은 0/1 로 몰려 있어 값 분포 자체가 데이터와 달랐다.

### 5.2 `np.zeros_like` 의 메모리 순서 (평가)

`density_match_binarize` 가 **모든 변이에 대해 density 0.0 을 보고**했다.
원인은 numpy 의 조용한 함정이다.

```python
out = np.zeros_like(samples)      # order='K' → 입력의 메모리 순서를 물려받는다
flat = out[i].reshape(-1)         # 비연속 배열이면 뷰가 아니라 복사본
flat[top] = 1.0                   # 쓰기가 버려진다 (예외도 경고도 없다)
```

`sample()` 이 torch 의 `permute` 결과를 numpy 로 넘기므로 C-연속이 아니었다.
`np.shares_memory` 로 확인한 결과 뷰가 아님이 확정됐다. C-연속 배열을 명시적으로
만들고 평평한 인덱스로 직접 쓰도록 고쳤다.

### 5.3 그래서 선행 negative 는 뒤집히는가 — 아니다

여기서 멈추면 안 된다. **2026-06 의 MLP-DDPM negative 기록도 같은 버그가 있는
샘플러로 만들어졌다.** 그렇다면 "MLP 는 시간축을 못 배운다"는 진단이 사실은
샘플러 버그였을 수 있다. 아키텍처 교체의 공을 주장하려면 이걸 반드시 확인해야 한다.

그래서 **저장된 MLP 가중치를 재학습 없이 고친 샘플러로 다시 샘플링**했다
(`experiments/refair_mlp_baseline.py`).

| 군 | density | autocorr | JS_profile | H0 runs | raw 평균 |
|---|---|---|---|---|---|
| REAL | 139.0 | 0.8135 | — | 5.68 | — |
| MLP 기록 (2026-06) | 418.2 | 0.5038 | 0.03037 | — | — |
| **MLP + 버그 샘플러** (재현) | 418.2 | 0.5038 | 0.03037 | 15.13 | 0.4979 |
| **MLP + 고친 샘플러** | 409.3 | 0.5047 | 0.02737 | 15.12 | 0.4902 |

두 가지가 확인된다.

1. 버그 샘플러가 **기록 수치를 소수점까지 재현**한다 → 베이스라인을 정확히 되살렸다.
2. 클리핑을 고쳐도 MLP 는 **거의 그대로다**(418→409, autocorr 0.504→0.505).

MLP 의 raw 출력 평균이 클리핑 여부와 무관하게 **0.49** 라는 점이 핵심이다.
클리핑은 누적 오차를 막을 뿐, **애초에 잘못된 분포를 학습한 모델을 구제하지 못한다**.
선행 negative 의 진단(평면화가 시간축 구조를 지운다)은 유효하다.

## 6. 결과 — 구조 지표

동일한 자(τ=0.5, 학습 데이터와 같은 이진화), 창 64개.

| 군 | density (840셀 중) | autocorr | JS_profile | H0 runs/cycle | 평균 구간길이 |
|---|---|---|---|---|---|
| **REAL (원곡)** | 139.0 | 0.8135 | — | 5.68 | 1.80 |
| MLP-DDPM (공정 재평가) | 409.3 | 0.5047 | 0.02737 | 15.12 | 1.96 |
| **full (위상+밀도 손실)** | **132.5** | **0.8251** | **0.00301** | **5.30** | **1.83** |

- 밀도 과밀 **해소**: 409.3 → 132.5 (원곡 139.0).
- 시간축 붕괴 **해소**: 0.5047 → 0.8251 (원곡 0.8135).
- cycle 프로파일 JS **9.1배 개선**: 0.02737 → 0.00301.
- 위상 지표(구간 수 5.30 vs 5.68, 구간 길이 1.83 vs 1.80)가 원곡과 근접.

> ⚠ **네 지표를 같은 무게로 읽으면 안 된다.** `full` 은 학습 중 **밀도**(L_dens)와
> **H₀ 구간 수**(L_topo)를 직접 회귀했고, cycle 프로파일은 밀도의 열별 분해라 사실상
> 같은 양이다. 즉 위 네 줄 중 **세 줄은 "손실이 작동했다"는 뜻이지 "분포를 배웠다"는
> 독립 증거가 아니다.**
>
> **손실과 독립인 지표는 시간축 autocorr 하나뿐이다** — 0.5047 → 0.8251 (원곡 0.8135).
> 어떤 항도 인접 스텝 일치율을 직접 최적화하지 않으므로, 이 개선만이 "시간 구조를
> 배웠다"의 독립 증거다. 다행히 그 지표가 애초의 실패 원인(0.5038 붕괴)과 정확히
> 같은 축이라, 주장 자체는 유지된다. 다만 **9.1배**라는 숫자를 앞세우는 것은 부적절하다.
>
> ablation(`conv` = 손실 없음)이 이 문제의 해답이다 — `conv` 도 autocorr 을 회복하면
> 그건 **아키텍처의 공**이고, `conv_topo`/`full` 에서만 회복되면 **손실의 공**이다.

---

## 7. 음악 생산 — 무엇을 듣게 되는가

OM 은 음악이 아니다. 들으려면 Algorithm 1 을 통과해야 한다.

**2단 선별** — 트랙마다 후보 40개를 만들고

1. **구조 게이트**: 원곡과의 음고분포 JS 가 중앙값 이하인 것만 통과
2. **미적 랭킹**: 통과한 것 중 **협화도** 최대

협화도만 쓰는 이유 — 2026-06-13 미적 지표 실험에서 합성 지표(협화도 + 성부진행 + 도약억제)는
calibration 에 실패했다(셔플이 원곡보다 높은 점수). 성분별로 뜯어보니
**협화도만 유효**했고, 성부진행·도약은 오히려 hibari 를 페널티했다.
(당시 그 원인을 "2성부 음역 분리"로 적었으나 **2026-08-10 확인 결과 사실이 아니다** — 두 성부의 pitch 집합은 완전히 동일하다([52,81], 교집합 17 = 합집합 17). 실제 원인은 위상 이동된 같은 재료가 **악기 라벨 없이 하나로 합쳐진** 스트림에서 측정되기 때문으로 보인다 — 미검증 가설)
(`project_aesthetic_rerank_negative_0613`). 검증을 통과한 성분만 쓴다.

**후보 공간의 온도 축** — NodePool 온도를 {1.0, 2.0, 3.0, 4.0} 로 돌려 후보를 넓힌다.
어느 온도가 더 듣기 좋은지는 위 랭킹이 고르게 한다.

**연주 레이어 (알고리즘 아님)** — MIDI 기록 시 세기만 손댄다. 음고·리듬은 그대로다.
이는 **피아노 연주 관습**이지 hibari 의 구조에 대한 주장이 아니다
(예전에 "2성부 음역 분리"를 근거로 적었으나 그 전제가 틀렸다 — 바로 위 §7 각주).
낮은 음은 페달 울림으로 받치고(pitch < 55 → −7),
위 성부를 앞으로 내며(pitch ≥ 72 → +9), 같은 순간에 음이 몰리면 전체를 눌러 탁함을 막는다
(onset 4개 초과분마다 −3). **연구 주장과 무관한 렌더링 선택**이므로 구분해 적는다.

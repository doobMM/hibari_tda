What It Is

1. 이 도구는 “코드 전체를 외우지 않아도 되는 조종석”입니다

Jarvis 스타일 대시보드의 목적은 코드 리뷰 전에 “어디부터 봐야 하는지”를 줄여주는 것입니다. 파일을 하나씩 열어 헤매기 전에, 파이프라인을 단계별로 펼치고 함수 단위로 바로 이동하게 합니다.

왼쪽

파이프라인 단계와 모듈 트리. 어떤 파일이 어느 단계에 속하는지 보여줍니다.

가운데

선택한 파일의 Python 코드 원문. Prism 하이라이트로 코드 읽기 부담을 줄입니다.

오른쪽

선택한 함수의 역할, 인자, 기본값, 반환값, 라인 범위를 요약합니다.

아래 상태바

현재 모듈, 현재 함수, 라인 범위, 시각을 계속 보여줘 탐색 위치를 잃지 않게 합니다.

비전공자 관점으로 말하면, 이 대시보드는 “코드가 실제로 어떤 순서로 음악을 분석하고 생성하는지”를 연구 파이프라인의 목차처럼 볼 수 있게 해줍니다.
대상 파일: tda_pipeline/docs/pipeline_dashboard.html2 / 15

3. HTML은 실행 중 분석하지 않고, 생성 시점에 이미 코드 정보를 품고 있습니다

1

MODULE_FILES

어떤 Python 파일을 읽을지 고정 목록으로 정의합니다.

2

parse_module

각 파일을 읽고 AST 트리로 변환합니다.

3

_extract_func

함수 이름, 클래스, 라인, 인자, 반환 타입을 뽑습니다.

4

_get_recent_lines

git log --since=30 days ago로 최근 수정 라인을 찾습니다.

5

build_html

모듈 데이터와 트리 데이터를 HTML 템플릿에 삽입합니다.

MODULE_FILES -> parse_module()
             -> source / line_count / functions[]
             -> recently_modified 표시
PIPELINE_TREE -> 왼쪽 탐색 트리
MODULES + TREE -> pipeline_dashboard.html 안에 정적 JSON으로 삽입
그래서 대시보드를 열 때 Python이 다시 돌지는 않습니다. 브라우저는 이미 HTML 안에 들어 있는 JSON을 읽어서 트리와 패널을 그릴 뿐입니다.

6. 모듈은 “음악을 데이터로 바꾸고, 구조를 찾고, 다시 음악으로 돌리는” 순서로 배치됩니다

pipeline.py전체 과정을 순서대로 부르는 지휘자단계 연결, 캐시, 설정 전달이 맞는가

Publishing and Privacy

11. 현재 GitHub Pages 기본 배포에는 이 코드 대시보드가 포함되지 않습니다

현재 Pages workflow는 hibari_dashboard, tonnetz_demo, filtration_viz, shared, 그리고 tda_pipeline/index.html 중심으로 사이트를 조립합니다. tda_pipeline/docs/pipeline_dashboard.html은 자동 복사 대상이 아닙니다.

장점

대시보드는 HTML 안에 Python 소스 전체를 삽입합니다. 자동 공개되지 않는 현재 상태는 민감정보 비공개 기본값에 맞습니다.

공개하려면 필요한 일

workflow에서 docs/ 또는 특정 HTML 파일을 _site로 복사해야 합니다. 공개 전에는 코드와 데이터에 민감정보가 없는지 먼저 확인해야 합니다.

공개 전 점검: API 키, 로컬 경로, 실험 미공개 결과, 개인 메모, GitHub 토큰, private 데이터 경로가 HTML 안에 들어가지 않았는지 확인해야 합니다.
workflow: .github/workflows/pages.yml12 / 15
Limitations

12. 이 인터페이스가 잘하는 것과 못하는 것을 분리해야 합니다

잘함: 구조 파악

어떤 파일과 함수가 파이프라인의 어느 단계에 속하는지 빠르게 보여줍니다.

잘함: 함수 단위 이동

라인 범위와 설명이 바로 보이므로 코드 리뷰의 진입 비용이 낮습니다.

못함: 동적 실행 추적

실제 런타임 호출 순서, 브랜치, 데이터 값은 보여주지 않습니다. 정적 분석 결과입니다.

못함: 테스트 판정

빨간 점은 최근 수정 표시일 뿐, 테스트 실패나 논문 수치 불일치를 직접 말해주지 않습니다.

못함: 완전한 호출 그래프

대시보드는 코드 보기 중심입니다. 깊은 호출 관계는 gen_code_map.py 쪽이 더 적합합니다.

주의: docstring 품질 의존

오른쪽 설명 패널은 docstring과 타입 힌트가 충실할수록 좋아집니다.

정적 스냅샷이므로 코드 변경 후 재생성 필요13 / 15

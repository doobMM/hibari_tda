설계도 — 어디를 건드리면 무엇이 바뀌나

이 연구는 곡을 점 23개로 바꾸고, 점 사이에 자를 대고, 자의 눈금을 늘려 가며 생기는 고리를 찾습니다. 그 고리들의 출석부가 새 음악의 설계도입니다.

01곡을 점으로 — note 23개

02점 사이의 거리 — 자가 넷 있다

두 note가 얼마나 가까운가. 이 질문의 답이 하나가 아닙니다. 자를 넷 준비해 뒀습니다.

⚠ 남는 것과 사라진 것을 갈라 둡니다. 남는 것 = "곡마다 최적 도구가 다르다"는 관찰. 철회한 것 = "어떤 곡 성격이 어떤 자를 부른다"는 설명 — 사후 해석이었고, 2026년 8월 재산출에서 5곡 중 3곡의 최적 자가 바뀌면서 근거가 사라졌습니다.
⚠ frequency 와 DFT 는 엄밀히는 거리(metric)가 아닙니다. frequency 는 동일성·삼각부등식을, DFT 는 동일성을 위반합니다 — 다른 두 note 의 거리가 0 일 수 있다는 뜻입니다. 그래도 지속 호몰로지를 돌릴 수 있는 근거는 Heo·Choi·Jung (2025) Thm 3.4 (path-representable)에 있습니다. 거리 공리 대신 더 약한 조건이면 충분합니다.

03자 둘을 섞는다 — α

둘 중 하나를 고르는 대신, 섞습니다. 섞는 비율이 α 입니다.

dα(a,b) = α · d빈도(a,b) + (1 − α) · d음악(a,b) α = 0 → 순수 음악적 거리 (hibari 는 DFT) α = 1 → 순수 빈도 거리 정본 → α = 0.25 (빈도 25% + DFT 75%)
두 행렬은 각각 [0,1] 로 정규화한 뒤 섞습니다. · musical_metrics.py:329

α 를 돌리면 고리의 개수 자체가 바뀝니다. 자를 바꾸면 무엇이 "가깝다"인지가 바뀌고, 그러면 어떤 고리가 생기는지가 통째로 달라지기 때문입니다. LIVE 계기판의 MATERIAL 버튼이 바로 이 α 입니다.

α 뱅크를 불러오는 중…
⚠ α 는 손잡이로 쓸 수 없습니다 (2026-09-05 계측). 눈금 6 × 시드 60 으로 상호정보량을 재니, α 는 유의하게 반응하지만(p=0.0002) 방향이 없습니다(ρ = −0.22). 값이 오르내리기만 해서 "더 복잡하게"라는 지시를 따라갈 수 없습니다. 그래서 계기판에서 노브가 아니라 선택 버튼으로 뒀습니다.
반면 밀도·높낮이·음길이는 세 개 모두 천장의 98~100%, ρ = 0.99 로 방향이 있습니다.

04눈금을 늘린다 — 여과

거리가 정해지면 이제 문턱 s 를 하나 잡습니다. 거리가 s 이하인 점들을 이어 붙입니다. s 를 0 에서부터 키우면 점들이 점점 이어지며 도형이 자랍니다. 이 자라는 도형들의 열이 여과(filtration)이고, 여기서 쓰는 방식이 Vietoris–Rips 입니다 — 서로 다 가까운 점들의 묶음을 하나의 조각으로 봅니다.

시간을 섞는 또 하나의 손잡이 — rate

거리 행렬은 사실 두 조각을 더한 것입니다. 같은 악기 안에서의 관계(intra)와 두 악기 사이의 관계(inter)입니다. 그 비중이 rate 입니다.

w(rate) = wintra + rate × winter rate : 0 → 1.5

rate 를 키우면 두 성부가 서로를 더 강하게 끌어당깁니다. hibari 의 두 성부는 음역이 아니라 위상으로 나뉘어 있어서(쓰는 음 집합은 같습니다) 이 값이 실제로 구조를 바꿉니다.

05고리가 태어나고 죽는다 — H₁

s 를 키우는 동안 어떤 고리는 일찍 생겨 오래 버티고, 어떤 고리는 생기자마자 메워집니다. 각 고리를 (태어난 s, 죽은 s) 한 쌍으로 적은 것이 지속 다이어그램이고, 가로 막대로 그리면 바코드입니다. 긴 막대 = 웬만해선 안 메워지는 구조, 짧은 막대 = 잡음.

hibari 정본 설정(DFT · α=0.25)에서 살아남는 고리는 K = 14 개입니다.
고리 하나 = note 몇 개의 묶음입니다. 예를 들어 [0, 1, 2, 6, 8, 9] 는 "0·1·2·6·8·9번 note 가 원을 이루며 서로 이어져 있다"는 뜻입니다.

06출석부 — 중첩행렬

여기서 시간이 돌아옵니다. 곡을 시점 순서대로 훑으며, 각 시점마다 어느 고리가 지금 켜져 있는가를 적습니다. 이 시점 × 고리 표가 중첩행렬(Overlap Matrix)이고, 이것이 새 음악의 설계도입니다.

OM[t, c] = 1 시점 t 에 고리 c 가 활성 0 아니면 먼저 연속값으로 재고 → 고리마다 다른 문턱 τc 로 0/1 을 정한다 (per-cycle τ)

07음을 뽑는 규칙 — 여기가 전부다

Algorithm 1 은 놀랄 만큼 짧습니다. 시점을 하나씩 지나가며 이렇게 합니다.

시점 j 에서 음을 하나 뽑는다: ① 켜진 고리가 하나도 없으면 → 예비 주머니에서 뽑되, 이웃 시점에 이미 쓴 음을 피한다 ② 켜진 고리가 있으면 → 켜진 고리들의 교집합에서 균등하게 하나 뽑는다 → 교집합이 비어 있으면 예비 주머니로 ③ 그 시점에 이미 있는 음이면 다시 뽑는다 (최대 50회)
generation.py:341 _sample_note_at_time

교집합이 핵심입니다. 여러 고리가 동시에 켜져 있으면, 그 고리들이 공유하는 note 중에서만 뽑습니다. 그래서 생성된 곡은 음이 매번 달라도 같은 뼈대를 갖습니다. 구조는 지키고 음은 새로 짓는 것이 여기서 나옵니다.

⚠ 온도와 음역 손잡이가 죽어 있는 이유가 정확히 여기 있습니다. 그 둘은 예비 주머니 안에서만 작동합니다. 그런데 hibari 정본 출석부는 빈 행이 0개이고 교집합도 비지 않아서, 주머니를 한 번도 뽑지 않습니다. 40회 반복 계측에서 온도 1.0↔5.0 의 출력이 비트 단위로 동일했습니다.
거꾸로 빈 행이 많은 출석부(α = 0 은 120중 65)에서는 같은 손잡이가 살아납니다 — 다만 그건 위상 구조가 무너진 자리라(고리가 1개뿐) 쓸 수 있는 설정이 아닙니다.

이 규칙을 바꾸면 무슨 일이 생기나 — 실제로 해봤습니다

②의 "균등하게"를 "곡에서 자주 나오는 음에 가중치를 주어"로 바꿔 봤습니다 (시드 30개씩). 음고 분포는 6.2% 좋아졌지만(Welch p=0.015, 비교 3개 Holm 보정 후 p=0.031), 협화도가 0.672 → 0.662 로 떨어졌습니다(Welch p=0.048). 이득과 손실이 거의 같은 크기입니다. 그리고 블라인드 청취에서 원래 규칙(균등)이 선택됐습니다. 그래서 채택하지 않았습니다. 지표가 좋아진다고 더 좋게 들리지 않습니다.

⚠ 위 두 p 값은 qmc_sampling_results.json 에 저장된 평균·표준편차·n(=30)에서 제가 다시 계산한 값입니다. 원 실험은 유의성 검정 결과를 저장하지 않았습니다. 프로젝트 노트에 적혀 있던 값(Holm 후 0.046 · 협화도 0.024)은 재현되지 않았습니다 — 노트 쪽이 틀렸다고 보고 여기서는 재계산값을 씁니다.

이미 재보고 막힌 곳 (다시 밟지 않도록)

  • 지표로 선호를 예측하지 못했습니다. 거리·협화도·역동성 세 계열 모두 n≈20 청취에서 실패했습니다. "지표가 좋다 ≠ 더 좋게 들린다."
  • 가장 복잡한 모델이 이기지 않았습니다. 정본 설정(DFT · gap0 · N=10)에서 FC 0.000348 < Transformer 0.000818 (Welch p = 1.7e-04) 이고, LSTM 은 0.1696 으로 FC 의 487배 나쁩니다. 파라미터가 많다고 좋아지지 않습니다. (단 이 순위는 설정에 딸려 있습니다 — gap=3 조건에서는 순위가 뒤집혀 Transformer 0.00276 이 FC 0.00354 를 이깁니다.)
  • 수치 최저가 최고가 아닙니다. 신경망(FC)이 JS = 0.00035 로 가장 낮지만 청취에서 원곡 모사로 들립니다. 규칙 기반 Algorithm 1(0.00902)이 더 낫게 들립니다.
  • 온도는 한때 반응하는 척했습니다. 주머니를 섞는 코드가 난수를 소비해 음의 96%가 바뀌었지만 방향은 0이었습니다. 셔플을 지우는 것이 수정이었습니다.
